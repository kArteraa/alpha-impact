# CODEX-TASKS — как выполнять задачи в Codex

Задачи для всех одни — `docs/tasks/BACKLOG.md`, порядок — `docs/TEAM.md`, пайплайн — `docs/PIPELINE.md`. Этот файл только про то, как тот же пайплайн запускается в Codex.

## Подготовка (один раз)

1. Codex читает `AGENTS.md` в корне — это зеркало `CLAUDE.md`, править только вместе.
2. Скилл `task` лежит в `.agents/skills/task/SKILL.md`. Если `codex --list-skills` его не показывает — скопировать папку в `.codex/skills/task/` (у Codex два места поиска в зависимости от версии).
3. `gh auth login`.
4. ECC для Codex ставится по желанию (`npx ecc-universal install --guided --harness codex`); пайплайн на него не завязан — шаги 2, 4, 6, 8 выполняются вручную по чек-листам из `docs/PIPELINE.md`.

## Запуск задачи

```
$task Выполни задачу AH-10
```

Скилл находит ключ, читает задачу в `BACKLOG.md`, создаёт ветку, пишет план и останавливается до одобрения. Дальше шаги 2–10 из `docs/PIPELINE.md`: тесты → код → коммит → чистка по чек-листу → `make check` до зелёного → ревью по чек-листу → ручная проверка → PR.

## Стоп-точки, на которых агент ждёт человека

- после плана
- перед ручной проверкой
- перед push и PR

## Если что-то не так

- Codex не видит скилл → копия в `.codex/skills/`, перезапуск
- агент предлагает действие вне плана → «не планировали», это нарушение `AGENTS.md`
- `make check` падает на чужом коде → не чинить чужое, писать владельцу в канбан
