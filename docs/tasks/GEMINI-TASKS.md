# GEMINI-TASKS — как выполнять задачи в Gemini CLI

Задачи для всех одни — `docs/tasks/BACKLOG.md`, порядок — `docs/TEAM.md`, пайплайн — `docs/PIPELINE.md`. Этот файл только про то, как тот же пайплайн запускается в Gemini CLI.

## Подготовка (один раз)

1. Gemini CLI читает `GEMINI.md` в корне — это зеркало `CLAUDE.md`, править только вместе.
2. Команда `/task` лежит в `.gemini/commands/task.toml`; после изменений — `/commands reload`.
3. `gh auth login`.
4. ECC для Gemini нет; шаги 2, 4, 6, 8 выполняются вручную по чек-листам из `docs/PIPELINE.md`.

## Запуск задачи

```
/task Выполни задачу AH-13
```

Команда подставляет аргумент в промпт, который велит: найти ключ, прочитать задачу в `BACKLOG.md`, создать ветку, написать план и остановиться до одобрения; затем шаги 2–10 из `docs/PIPELINE.md`.

## Стоп-точки, на которых агент ждёт человека

- после плана
- перед ручной проверкой
- перед push и PR

## Если что-то не так

- `/task` не находится → `/commands list`, проверить путь `.gemini/commands/task.toml`
- агент предлагает действие вне плана → «не планировали», это нарушение `GEMINI.md`
- `make check` падает на чужом коде → не чинить чужое, писать владельцу в канбан
