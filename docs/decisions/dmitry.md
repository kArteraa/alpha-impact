# Решения — Дмитрий Редняков

Личный файл журнала решений. Правила и файлы остальных участников — `docs/DECISIONS.md`.

- 2026-10-20: сервис — пакет в `backend/apps/services/` с `register(container)`; `main.py` находит сервисы сам, import-linter берёт их по шаблону `apps.services.*`, интеграционные тесты чистят все таблицы из миграций — новый сервис не требует правок общих файлов (AH-48)
- 2026-10-20: профиль читает только `df_Uid_data_hack.csv`; платежи загружает `counterparty` (AH-8), `df_Fid_Uid_link` не загружается вовсе — физлица не должны попадать в промпты, профилю они не нужны (AH-7)
- 2026-10-20: профили строятся для компаний с выручкой > 15 млрд и для заглушек; порог, веса и уверенности — в `apps/services/profile/config.yaml`, отрасли по префиксам ОКВЭД — в `industries.yaml` (AH-7)
- 2026-10-20: восемь факторов экспозиции — `key_rate`, `fx_rate`, `trade_logistics`, `commodity_prices`, `construction_demand`, `consumer_demand`, `labor_market`, `regulation`, значения 0…1; разметка новостей (AH-13) и предфильтр (AH-15) используют эти же имена (AH-7)
- 2026-10-20: `SYNTHETIC_U`, встречающийся больше одного раза, — заглушка: профиль без признаков с флагом `placeholder`, в группы не входит (AH-7)
- 2026-10-20: пользователь правит только выведенные признаки (`source` не `bank`), правка факта банка — `AccessDenied`; у компании без карточки и у заглушки фактов банка нет, правится любой признак; правки хранятся отдельно и повторным `seed` не затираются; `version` = версия расчёта + число правок (AH-7)
- 2026-10-20: имена признаков и флагов профиля согласованы со словарём каталога продуктов (`products/rules.yaml`, запись в `decisions/artem.md`): `CL_TYPE` — признак `cl_type` с исходными значениями, импорт — флаг `imports`; флаги `buyer_concentration` и `free_balances` профиль из таблицы компаний не выводит — первый требует графа платежей (AH-8), данных об остатках на счетах в кейсе нет (AH-7)
- 2026-10-20: профили строятся для компаний с выручкой > 15 млрд, для заглушек и для всех клиентов из таблицы компаний, привязанных к пользователям, — `no_card` получает только клиент, которого в таблице нет; правка `industry_class` принимает только известные классы (`industries.yaml` и `other`) и пересчитывает экспозиции при чтении профиля, сохранённые экспозиции остаются расчётом по данным банка (AH-53)
