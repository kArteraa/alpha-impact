# PIPELINE — один пайплайн задачи для любого агента

Задача выполняется одинаково, каким бы агентом человек ни пользовался: Claude Code, Codex или Gemini CLI. Различается только то, чем именно делается каждый шаг. Источник истины по правилам — `CLAUDE.md` (у Codex он зеркалится в `AGENTS.md`, у Gemini — в `GEMINI.md`; содержание одно). Точка входа — команда `task`:

| Агент | Как вызвать | Где лежит |
|---|---|---|
| Claude Code | `/task "Выполни задачу AH-7"` | `.claude/skills/task/SKILL.md` |
| Codex | `$task Выполни задачу AH-7` | `.agents/skills/task/SKILL.md` (копия в `.codex/skills/task/`, если Codex не видит `.agents`) |
| Gemini CLI | `/task Выполни задачу AH-7` | `.gemini/commands/task.toml` |

## Шаги и их реализация по агентам

| Шаг | Что должно произойти | Claude Code | Codex | Gemini CLI |
|---|---|---|---|---|
| 0 Ветка | `git switch dev && git pull && git switch -c <prefix>/AH-<n>-<slug>`; грязное дерево → стоп и вопрос | git | git | git |
| 1 План | Прочитать задачу в `docs/tasks/BACKLOG.md` (и в Jira, если просили), написать план: файлы, тесты, контракты, риски. **Стоп до одобрения** | `/ecc:plan` в plan mode | написать план в ответе и ждать «ок» | написать план в ответе и ждать «ок» |
| 2 TDD | Сначала тесты (RED), потом код (GREEN) по таблице типов | `/ecc:tdd-workflow` | вручную: тесты → `make test` падает → код → зелёный | вручную, так же |
| 3 Коммит | Естественный язык, списком, без префиксов и атрибуции | git | git | git |
| 4 Чистка | Убрать дубли, мёртвый код, лишние абстракции; ≤ 500 строк на файл; без комментариев | `/ecc:refactor-clean` | пройти по diff с чек-листом ниже | пройти по diff с чек-листом ниже |
| 5 Коммит | Если что-то изменилось | git | git | git |
| 6 Верификация | `make check` целиком: ruff, mypy, import-linter, pytest, npm test, npm run build; чинить до зелёного | `/ecc:verification-loop` | `make check` в цикле | `make check` в цикле |
| 7 Коммит | Если верификация потребовала правок | git | git | git |
| 8 Ревью | Чек-лист ревью ниже, правки, снова `make check`. **Стоп: попросить ручную проверку** того, что тесты не покрывают | `/ecc:code-review` | самопроверка по чек-листу | самопроверка по чек-листу |
| 9 Коммит | — | git | git | git |
| 10 Push и PR | **Стоп: спросить.** На «да»: `git push -u origin <branch>`, `gh pr create --base dev --title "AH-<n> · …"`, описание: что сделано / как проверить / риски; Jira → Review, если просили | gh | gh | gh |

## Типы задач

| Тип | Ветка | Шаг 2 |
|---|---|---|
| feat | `feat/AH-<n>-<slug>` | тесты на новое поведение, затем код |
| fix | `fix/AH-<n>-<slug>` | падающий регрессионный тест, затем исправление |
| изменение поведения | `feat/` или `fix/` по смыслу | обновить существующие тесты под новую спецификацию, затем код |
| refactor | `refactor/AH-<n>-<slug>` | без новых тестов; зелёно до и после |
| contract | `feat/AH-<n>-contract-<slug>` | контрактный тест → все реализации → `docs/CONTRACTS.md` |
| docs / chore | `docs/…`, `chore/…` | без TDD; коммит и верификация обязательны |

TDD обязателен для сервисов, `shared/` и логики фронта (хуки, состояние, API-клиент). Для чистой JSX-вёрстки шаг 2 — Vitest render-тест и зелёный `npm run build`.

## Чек-лист чистки (шаг 4)

- Нет кода, не нужного для одобренного плана
- Нет дублирования между сервисами; общее — только через `shared`
- Файлы ≤ 500 строк, функции делают одно
- Нет комментариев и закомментированного кода
- Нет дефолтов и фолбэков, не одобренных явно
- Имена говорят сами; магические числа — в настройки

## Чек-лист ревью (шаг 8)

- Сервис импортирует только `shared.*` и себя (`test_import_boundaries` зелёный)
- Контракт не изменён, или изменён по пайплайну «contract»
- Каждый `Claim` имеет `source_ref`; `CounterpartyContext` без чужих идентификаторов; `silent` обработан в UI
- Новая зависимость → строка в `THIRD_PARTY_NOTICES.md`; lock-файл обновлён
- LLM вызывается только через `apps/services/llm`
- Тесты проверяют поведение, а не реализацию; нет тестов, которые всегда зелёные
- README и `docs/` не разошлись с кодом

## Правила, общие для всех

- Никогда не коммитить и не пушить в `dev`/`main`
- Никаких `Co-Authored-By` и упоминаний агента в коммитах и PR
- Коммит только по шагам пайплайна или по просьбе
- Если шаг нельзя выполнить (нет инструмента, падает окружение) — остановиться и сказать, что именно, не обходить
